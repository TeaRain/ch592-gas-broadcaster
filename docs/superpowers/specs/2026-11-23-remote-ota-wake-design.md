# CH592 普通窗口免按键 OTA 设计

## 目标与动机

在 HA 的现有固件更新实体中点击“安装”后，集成自动等待设备的普通广播窗口，通过一次受控 GATT 写入请求设备进入现有 OTA 模式。此后仍使用当前 Image B 上传、协议 8 CRC、END、IAP 和目标版本 BTHome 广播确认，不再要求用户现场按 B。

这是共同早期分支上的最小功能移植，不换用参考项目的固件、燃气模型或集成。

## 已选方案与取舍

- 采用 **300 ms 普通可连接窗口 + 50 ms 广播间隔**，每分钟约 6 帧；当前为 100 ms + 20 ms、约 5 帧。
- 相比 300 ms + 20 ms 的 15 帧，消息增量由 200% 降为 20%，理论广播功耗预算约 0.2～1 µA，但必须实测。
- 不采用 100 ms 间隔：只有约 3 帧，BTHome 冗余和连接机会偏少。
- 不采用每 5 分钟一次可连接窗口：虽然更省电，但点击更新后的等待时间过长。
- 不在一次启动内运行时重建 Broadcaster/Peripheral Role；收到唤醒请求后复用当前 DataFlash 请求和软复位路径。

## 固件改动边界

1. 普通阶段改为支持连接的 Peripheral/GATT 初始化，周期广播使用 Legacy `ADV_IND`。
2. 普通周期广播窗口由 100 ms 调整为 300 ms，广播间隔由 20 ms 调整为 50 ms；BTHome 内容、300 ms 采样和 60 s 周期不变。
3. 普通阶段仅注册必要的 GAP/GATT 和 `0xFEE0/0xFEE1` 控制入口，只接受固定长度、固定 magic 的 `ENTER_OTA` 命令；拒绝普通阶段的 ERASE、PROGRAM、CRC、END 等命令。
4. 有效请求写现有 `OtaMode_Request()`，按 manual 原因处理；先完成 GATT 应答，再由正常任务延迟软复位，防止回调重入。
5. 连接建立后，广播关闭定时器不得断开已有连接；未连接时仍按窗口关闭并恢复休眠。
6. 复位后完全复用现有 OTA Peripheral、Image B 写入、协议 8 CRC、END 和 IAP。IAP 本身不改。
7. 保持原始 `uint32` 计数、DataFlash 双块追加日志、P/N 调阈值及回显、按 B 和三天定时 OTA。

## HA 改动边界

1. 保留现有 `update` 实体、清单轮询和下载逻辑。远程唤醒前必须取得并校验清单中的 size、CRC32 和 SHA-256，任一缺失或不匹配则不连接设备。
2. 在现有上传前增加编排阶段：`waiting_window → connecting_control → requesting_ota → waiting_ota_ad → uploading → rebooting`。
3. 只在用户明确安装或已有合法 OTA 任务时主动连接；普通版本轮询和日常 BTHome 接收不主动连接。
4. 复用普通 BTHome 回调、ESPHome 主动连接、设备锁、准备锁、取消和任务超时。错过短窗后等待后续广播有限重试，不高频空转。
5. `ENTER_OTA` 后允许设备复位断开控制连接，再等待新的原始 `0xFEE0` OTA 广播；不得把旧缓存广播当作切换成功。
6. 手动安装与现有自动安装互斥。若存在待写阈值，仍先写阈值，成功后同窗口升级；阈值失败保留待写并阻止本次升级。
7. 继续以序号更新的目标版本 BTHome 广播作为成功条件。首版不新增 HA 重启后的安装续传；重启或取消后设备按现有 OTA 超时安全退出。
8. 更新进度和中文状态说明覆盖等待、连接和唤醒阶段，避免点击后看似没有开始。

## 明确不做

- 不改变 HA offset、三值燃气模型或能源统计来源。
- 不恢复设备端真实燃气值写入，不合并参考项目后续燃气逻辑。
- 不修改 OTA 镜像布局、CRC 算法、IAP 或完整烧录包结构。
- 不删除按 B、三天定时 OTA 或阈值跨重启持久化。
- 不增加常驻 BLE 连接，不在后台下载固件，不实现断点续传。
- 不把固定 magic 描述为身份认证；它只防止误帧。普通入口不暴露任何 Image B 写命令。

## 验证与实机门槛

1. HA 测试先覆盖：完整校验后才唤醒、错过窗口重试、取消、重复点击互斥、旧 OTA 广播防误判、阈值优先后升级、失败不发送 END。
2. 固件主机测试覆盖：广播参数、普通阶段仅接受唤醒命令、错误 magic/长度拒绝、写请求后复位、连接不被窗口定时器断开。
3. 保留并通过 `INT_SOFT` 和中断 `mret` 构建检查，不以未经检查的通用 GCC 产物发布。
4. 旧固件第一次通过按 B 或三天窗口升级；新固件再完成一次完全不按键的实机 OTA，并确认版本、原始计数、HA 读数和阈值均保留。
5. 功耗至少比较当前版本与 300 ms + 50 ms 版本；条件允许时增加 Peripheral/GATT + 原 100 ms 组，分离 Role 开销与窗口开销。分别观察被动/主动扫描、漏窗率、连接重试和 CR2032 电压下陷。
6. 未经实机验证，不宣称连接可靠性、1～3 分钟耗时或功耗估算已经达到。
